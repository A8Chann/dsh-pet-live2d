# 桌宠的领域模型

这一层是"宠物怎么决定自己长什么样"的规则，既不是 Cubism 引擎的事、也不是 React 的事。

## 四个词

| 词 | 含义 |
|---|---|
| **槽位** `slot` | 一个**互斥组**（眼部 / 右手 / 氛围：冒爱心 …）。跨槽位可以同时生效 |
| **选项** `option` | 槽位里的一个选择，可以带**多个表达式**（「白魔爪」= 桌面粉魔爪 + 魔爪换色） |
| **池子** `pool` | 一个槽位在某个场景（摸鱼 / 某个会话相位）下的候选表 |
| **条目** `entry` | 池子里的一行：`{ label, weight }`；`label: null` = 「默认」 |

运行时只有一个入口：`chooseSlotOption(slot, option, satisfy?)` —— 面板点选、摸鱼抽中、
相位抽中、配对补点，全走它。

## 「默认」＝回到默认（清空这个槽位）

**这是个被来回改过一次、最后定回来的语义**，别想当然：

- 它**不是**"这次不动"。曾经为了修"摸鱼把用户手选的爱心眼擦掉"改成"不动"，结果制造了
  更糟的坑：**掷中过的选项再也回不去** —— 用户拿 `默认 10 : 脸红 1` 的池子证明给我看，
  脸红一旦被掷中（1/11）就一直挂在脸上，因为"不动"永远不会关掉它。
- 想表达"这个槽位完全不参与"，正确做法是**条目删光或权重归 0**。
- 池子过滤只看"还有没有有份量的条目"（`entriesOf(slot).length > 0`）。
  **只剩「默认」的池子仍然要抽** —— 曾经用"有没有真选项"过滤，等于让"清空"永远轮不到。

## 摸鱼：每个池子各掷一次

- 静置 `fidgetQuietMs` 之后开抽，**池子里每个槽位都掷一次**（不是"这次只动一两个"），
  然后按槽位顺序逐个应用。
- 抽签阶段：条目权重 ≤ 0 不进池；动作选项还要过动作守卫（前提不成立就不抽它）。
- **应用阶段要再查一遍前提**：所有池子都是按"这一轮开始前"的状态掷的，
  右手掷成「双手比耶」之后，同一轮里被抽中的「自拍」其实已经没有前提了 ——
  不重查就是用户看到的"先比耶、再拍照"。
- 抽到「默认」→ `chooseSlotOption(slot, null)` 清空这个槽位（见上）。
- 诊断：`fidgetTally()` 给出每个槽位/条目被掷中的次数与 `poolSize`。
  **计数要连"掷到默认"一起记**，否则"这个槽位多久动一次"这类断言会失真。

## 关系两种，归属都是**选项**

键是 `<槽位>:<选项标签>`（不是"池子里的某一条"）—— 同一个姿势在摸鱼表、相位池、右键面板
里看到的是同一份关系。默认值来自 `pet.json` 的 `options[].pairs` / `options[].requires`，
用户在设置界面改过的覆盖它，合成入口是 `effectiveOption()`。

| 关系 | 语义 | 运行时怎么用 |
|---|---|---|
| **同时** `pairs` | 选了它就一起点亮 | `applyExpressions` 里的**不变量**：源头还选中，目标就一直亮；源头被清掉，目标跟着收 |
| **前提** `requires` | 必须先处于那个状态 | 抽签时是**闸门**；手动点选时**由插件补齐** |

两条硬经验：

- **`pairs` 必须是不变量，不能是一次性副作用。** 只在"选中那一刻"点一次的话，之后任何
  把它清掉的东西（摸鱼重掷、相位接管、换宠物）都会让它**永久**失效 —— 用户报的"冒爱心
  一直出不来"就是这个。放在 `applyExpressions`（所有路径都过的漏斗）里重算。
- **顺带：先更新选择、再推 pin。** 反过来的话不变量读到旧状态，把眼部切回「默认」时
  源头看起来还是爱心眼，配对又把冒爱心补回来（表现是"切回普通眼，氛围回不去"）。

### 前提的两种写法（决定了能不能自动满足）

| 写法 | 形态 | 能自动补吗 |
|---|---|---|
| `pet.json` 的 `motionGuards` | 槽位 = 标签**白名单** | 不能，只能拦（喷水要鲸鱼，而鲸鱼有"头顶""放桌上"两种） |
| 选项上的 `requires` | 槽位 = **某一个标签** | 能 —— 手动点选时插件先把它点上 |

所以给「自拍」配「前提：右手 = 掏出手机」要用**选项上的 `requires`**：
摸鱼抽签时手机不在手就不抽它；手动点选时插件会先把手机掏出来（跟点「挤番茄酱」会把
蛋包饭端上来是同一套），不会"点了没反应"。

## 相位池 = 摸鱼那套

会话相位（`thinking` / `tool` / `waiting` / `done` / `failed`）下面是"槽位 → 条目表"，
机制与摸鱼完全一致，默认值来自 `pet.json` 的 `looksByPhase`（读成"每槽位一条、权重 1"）。

设置界面里**全部相位一开始就列出来**（用户问过"列表是空的、点添加才有默认值，这正常吗"）：

- 每行显示的是**有效池子**（有覆盖用覆盖，没有就用默认），行头标「默认 / 已改过」；
- 只有**改过**的行才有 `×`（= 恢复默认）；
- 覆盖**只在真的编辑时才落盘**（`setPhasePool` 会把有效池子整份物化再改那一张）——
  这样"看一眼"不留痕迹，以后宠物更新了默认值照样吃得到。

## 装扮槽是另一类

眼镜 / 发饰 / 魔爪 / 巴菲 / 桌布 / 手机换色 这六个（`OUTFIT_SLOTS`）是**穿在身上**的：

| 场景 | 临时表情 | 装扮 |
|---|---|---|
| 会话相位开始 / 结束 | 相位接管，结束就撤 | 不动 |
| 「归位」 | 清空 | 保留 |
| 重启 / 刷新 | 回默认 | 从 localStorage 穿回来 |

实现上就一句话：`commitPins` 里装扮的 pin **最后合并**，所以相位的槽位拥有权压不过它。

## 存档：三个键 + 剪枝

| 键 | 内容 |
|---|---|
| `dsh-pet-live2d.settings.v1` | 手感滑杆（`TUNING`） |
| `dsh-pet-live2d.settings.v2` | 池子覆盖 + 关系覆盖 + flags（`PHASE_OVERRIDES`） |
| `dsh-pet-live2d:outfit` | 当前穿的装扮（跨启动） |

- **加载清单时要剪一遍存档**（`pruneOverrides`）：删掉已经不存在的槽位/选项的覆盖。
  改过槽位结构（氛围拆成三个、自拍独立成槽）之后，旧键不报错、只会**静默失效**，
  甚至让"关系指向一个不存在的槽位"、配对再也点不亮。
- 装扮存档读回来时要**校验 label 在当前 `pet.json` 里还存在**，对不上就当没存过 ——
  换模型或改配置之后存档可能对不上，不能凭空造一个选项出来。
- 设置界面两个入口（DSH 设置页那一节）共用**模块作用域的 store** + 订阅广播，
  所以值永远是一份。
